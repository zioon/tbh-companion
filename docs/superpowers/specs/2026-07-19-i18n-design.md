# TBH Companion 多语言（i18n）支持设计

**日期**：2026-07-19
**状态**：待评审
**作者**：基于用户需求与现有架构推导

## 1. 目标与范围

### 1.1 目标
为 TBH Companion 应用添加完整的多语言支持，让玩家可以选择 UI 语言，覆盖：

- **Renderer UI**：主窗口所有 Tab、Overlay 浮窗、BoxTracker 窗口中的全部可见文本（Tab 标题、按钮、表头、状态消息、对话框、Tooltip、错误提示等）
- **主进程用户可见文本**：系统托盘菜单、系统通知、原生对话框标题与过滤器、启动错误框

### 1.2 支持语言
| 代码 | 语言 | 角色 |
|------|------|------|
| `en` | English | 源语言 + 兜底 |
| `zh-CN` | 简体中文 | 第一翻译目标 |
| `ja` | 日本語 | 第二翻译目标 |
| `ko` | 한국어 | 第三翻译目标 |

### 1.3 不在范围内（YAGNI）
- 文档（`docs/`）的翻译 — 文档面向开发者，保持英文
- 控制台日志（`createLogger` 输出）— 调试用，保持英文
- `core/` 纯领域逻辑中的常量字符串 — 例如 `BoxOpenStats.label`（"Common chest"）这类**数据驱动**的字符串，由数据层（`gamedata.json`）控制，不在本设计内翻译。仅在渲染层通过映射表展示时翻译
- 错误堆栈与 `reportError` 上报的原始错误消息
- 第三方内容：Steam Market 名称、游戏内物品名（由 `gamedata.json` 提供，应通过单独的 catalog i18n 处理，超出本次范围）

### 1.4 库选型（已确认）
- **i18next** + **react-i18next**：生态成熟、支持命名空间/插值/复数/懒加载/语言切换热更新
- 主进程与渲染进程**各自初始化独立的 i18next 实例**（Electron 双进程模型必需）
- 共享翻译 JSON 资源，由两个实例引用

## 2. 架构

### 2.1 分层遵循
严格遵循 `AGENTS.md` 的四层架构：

| 层 | 角色 | 改动 |
|----|------|------|
| `shared/` | 类型 + 通道名 + **翻译 JSON 数据** | 新增 `locales/{lang}/{ns}.json` 与 `language.ts` 类型定义 |
| `core/` | 纯领域逻辑 | **新增 `i18n/`** 子模块：纯工厂 `createI18n(config)` 与 key 类型推导；零 Electron/React 依赖 |
| `main/` | Node 进程 | 新增 `i18n.ts`：调用工厂初始化主进程实例，向 `NotificationService`、`trayService`、`appState` 注入 `t()` |
| `renderer/` | React UI | 新增 `i18n.ts`：调用工厂 + `react-i18next` 初始化，导出 `useTranslation` 包装、`I18nProvider` |
| `preload/` | contextBridge | **无改动**（语言通过现有 `SAVE_CONFIG` 通道流动） |

**为什么放 `shared/`？** `AGENTS.md` 写「shared = 类型 + 通道名，无运行时逻辑」，但 `notificationCatalog.ts` 已经包含运行时常量与函数（`DEFAULT_NOTIFICATION_PREFS`、`sanitizeNotificationVolume`），说明 shared 允许**数据 + 纯工具**。翻译 JSON 是纯数据，与 `notificationCatalog.ts` 性质一致，放 shared 让主进程与渲染进程都能直接 import，避免重复维护。

### 2.3 i18next 工厂（core 层）
```typescript
// app/src/core/i18n/factory.ts
import i18next from "i18next";
import type { AppLanguage } from "../../../shared/language";

/** 已解析的具体语言（不含 "auto"）。 */
export type ResolvedLanguage = Exclude<AppLanguage, "auto">;

export interface CreateI18nOptions {
  language: ResolvedLanguage;    // 调用方必须先 resolveLanguage("auto", ...) 再传入
  fallback: ResolvedLanguage;    // 始终为 "en"
  resources: Record<ResolvedLanguage, Record<string, object>>; // 由调用方注入
}

/** 纯工厂：不依赖 electron/react，可被 main 与 renderer 复用。同步初始化（资源内联）。 */
export function createI18n(opts: CreateI18nOptions): typeof i18next {
  const instance = i18next.createInstance();
  instance.init({
    lng: opts.language,
    fallbackLng: opts.fallback,
    resources: opts.resources,
    defaultNS: "common",
    ns: [
      "common", "tabs", "settings", "live", "inventory", "market",
      "loot", "chests", "lookup", "pets", "about", "liveMemory",
      "tray", "notifications", "dialogs",
    ],
    interpolation: { escapeValue: false }, // React 已防注入
    returnEmptyString: false,              // 空翻译回退到 fallbackLng
  });
  return instance;
}
```

**注意**：
- `resources` 由调用方注入而非用 `i18next-http-backend` 加载，因为 Electron 打包后文件位于 `asar` 内，HTTP 加载需自定义协议；直接 import JSON 让 Vite/electron-builder 内联到 bundle，零运行时 I/O
- 工厂只接受**已解析**的具体语言，"auto" 必须由调用方在调用前用 `resolveLanguage()` 解析（这样工厂无需知道 system locale，保持纯函数特性）
- 资源内联时 `i18next.init()` 实际为同步，但返回类型是 `Promise<TFunction>`；调用方若需严格 Promise 可 `await instance.init()`

### 2.4 语言类型与默认值
```typescript
// app/shared/language.ts
export const APP_LANGUAGES = ["en", "zh-CN", "ja", "ko"] as const;
export type AppLanguage = (typeof APP_LANGUAGES)[number] | "auto";

export const DEFAULT_LANGUAGE: AppLanguage = "auto";

/** 将 "auto" 解析为具体 BCP-47 标签，未知 locale 回退 en。 */
export function resolveLanguage(
  language: AppLanguage,
  systemLocale: string,
): "en" | "zh-CN" | "ja" | "ko" {
  if (language !== "auto") return language;
  const lower = systemLocale.toLowerCase();
  if (lower.startsWith("zh")) return "zh-CN";
  if (lower.startsWith("ja")) return "ja";
  if (lower.startsWith("ko")) return "ko";
  return "en";
}
```

```typescript
function sanitizeLanguage(raw: unknown): AppLanguage {
  if (typeof raw !== "string") return DEFAULT_LANGUAGE;
  if (raw === "auto") return "auto";
  if ((APP_LANGUAGES as readonly string[]).includes(raw)) return raw as AppLanguage;
  return DEFAULT_LANGUAGE;
}
```

## 3. 主进程集成

### 3.1 i18n 实例与初始化
新建 `app/src/main/i18n.ts`。**关键**：`app.getLocale()` 必须在 `app.whenReady()` 之后调用，因此实例**懒初始化**：

```typescript
import { app } from "electron";
import { createI18n, type ResolvedLanguage } from "../core/i18n/factory";
import { resolveLanguage, type AppLanguage } from "../../shared/language";
import * as en from "../../shared/locales/en";
import * as zhCN from "../../shared/locales/zh-CN";
import * as ja from "../../shared/locales/ja";
import * as ko from "../../shared/locales/ko";
import type { AppConfig } from "../../shared/types";

const resources = { en, "zh-CN": zhCN, ja, ko } as const;

// 懒初始化：在 app.whenReady() 内由 initMainI18n() 首次调用时创建。
// 在此之前 t() 会回退到 key 本身（即英文源字符串），用于启动早期日志。
let instance: ReturnType<typeof createI18n> | null = null;

export function initMainI18n(config: AppConfig): void {
  const resolved = resolveLanguage(config.language, app.getLocale());
  if (!instance) {
    instance = createI18n({ language: resolved, fallback: "en", resources });
  } else {
    instance.changeLanguage(resolved);
  }
}

export function t(key: string, opts?: Record<string, unknown>): string {
  if (!instance) return key; // 启动早期兜底
  return instance.t(key, opts);
}

export function changeLanguage(lang: AppLanguage): void {
  if (!instance) return;
  const resolved: ResolvedLanguage = resolveLanguage(lang, app.getLocale());
  instance.changeLanguage(resolved);
}

export function getMainI18n(): ReturnType<typeof createI18n> {
  if (!instance) throw new Error("mainI18n not initialized — call initMainI18n first");
  return instance;
}
```

在 `app/src/main/index.ts` 的 `app.whenReady()` 内、创建窗口之前调用 `initMainI18n(config)`。`trayService`、`NotificationService` 等只在 `whenReady` 之后运行的代码可直接调用 `t()`。

### 3.4 渲染进程的语言同步
渲染进程的语言通过 `window.tbh.getConfig()` 拿到 `config.language`，并在 `saveConfig` 成功后用返回的最新 config 调用 `i18n.changeLanguage()`。无需新增推送通道（语言切换是用户主动操作，下次渲染窗口重启也会读到最新值）。

为支持三个窗口（main / overlay / boxTracker）实时同步：在 `TbhProvider` 内监听现有的配置变化（如果有 `onConfig` 推送就用，没有则在 `saveConfig` 返回后直接更新本窗口；其他窗口下次重启或手动操作时同步）。**MVP 接受单窗口即时、跨窗口下次重启同步的妥协**，避免新增 IPC 推送通道。

## 4. 渲染进程集成

### 4.1 i18n 实例与 Provider
新建 `app/src/renderer/i18n.ts`：
```typescript
import i18next from "i18next";
import { initReactI18next } from "react-i18next";
import { createI18n, type ResolvedLanguage } from "../core/i18n/factory";
import { resolveLanguage, type AppLanguage } from "../../shared/language";
// 资源 import 同主进程

let initialized = false;

export async function initRendererI18n(language: AppLanguage): Promise<typeof i18next> {
  const resolved: ResolvedLanguage = resolveLanguage(language, navigator.language);
  if (initialized) {
    await i18next.changeLanguage(resolved);
    return i18next;
  }
  const instance = createI18n({ language: resolved, fallback: "en", resources });
  instance.use(initReactI18next);
  await instance.init();
  initialized = true;
  return instance;
}

export function changeRendererLanguage(language: AppLanguage): Promise<void> {
  const resolved: ResolvedLanguage = resolveLanguage(language, navigator.language);
  return i18next.changeLanguage(resolved);
}

export { i18next };
```

### 4.2 Provider 接线
修改 `app/src/renderer/Root.tsx`：在最外层包一个 `I18nReadyGate`（在 i18n 初始化完成前显示空白/loading，避免首屏闪烁英文）。

`TbhProvider` 改造为在挂载时拉取 `getConfig()` 并初始化 i18n，初始化完成后渲染 children：
```typescript
export function TbhProvider({ children }) {
  const [i18nReady, setI18nReady] = useState(false);
  useEffect(() => {
    let mounted = true;
    window.tbh.getConfig()
      .then((cfg) => initRendererI18n(cfg.language))
      .then(() => mounted && setI18nReady(true))
      .catch(reportIpcError);
    // ... 其他 effect ...
  }, []);
  if (!i18nReady) return null;  // 或一个简单的 loading 占位
  return <TbhContext.Provider value={value}>{children}</TbhContext.Provider>;
}
```

### 4.3 翻译使用约定
- 函数组件：`const { t } = useTranslation(["settings", "common"]);` 然后 `t("settings.cache.clearPrices.title")`
- 非组件（如 `appTabs.ts` 这种纯数据）：改为返回 `id`，由组件层用 `t(\`tabs.\${id}\`)` 渲染。`getVisibleTabs` 重构为只返回 `TabId[]`，标签文本由 `AppTabBar` 用 `t()` 渲染
- 模板字符串中的英文：替换为 `t(key, { var: value })` 插值
- 静态常量字符串（如 `Overlay.tsx` 中的 `RATE_TIP`）：移到翻译 JSON，组件内用 `t("live.rateTip")` 取

### 4.4 Settings Tab 增加语言选择器
在 `Settings.tsx` 顶部「General」段新增：
```tsx
<Field label={t("settings.language.label")}>
  <Select
    value={config.language}
    onChange={(v) => saveConfig({ language: v })}
    options={[
      { value: "auto", label: t("settings.language.auto") },
      { value: "en", label: "English" },
      { value: "zh-CN", label: "简体中文" },
      { value: "ja", label: "日本語" },
      { value: "ko", label: "한국어" },
    ]}
  />
</Field>
```

切换后：
1. `saveConfig({ language })` → 主进程 `applyConfigPatch` → 主进程 i18n 切换 + 托盘重建
2. 返回的 next config → 渲染进程 `changeRendererLanguage(next.language)` → react-i18next 触发整树重渲染

## 5. 翻译 Key 约定

### 5.1 命名规范
- 嵌套 key，按"功能.子功能.用途"：`settings.cache.clearPrices.confirm`
- 插值用 `{{varName}}`：`"updateAvailableBody": "TBH Companion v{{version}} is available."`
- 复数用 i18next 内置 `_one` / `_other` 后缀：`"slots_one": "{{count}} slot used"`, `"slots_other": "{{count}} slots used"`
- 不在 key 中嵌入 HTML；需要富文本时用 `<Trans>` 组件

### 5.2 不翻译的内容
- 数字、日期：用 `Intl.NumberFormat` / `Intl.DateTimeFormat`（i18next 自动按当前语言走 Intl）
- 物品名、英雄名：来自 `gamedata.json`，本设计不涉及
- 错误堆栈：保持英文

### 5.3 缺失翻译的兜底
- i18next 配置 `fallbackLng: "en"` + `returnEmptyString: false`
- 翻译不完整的 key 自动回退到英文，不会显示空白
- 启用 `i18next-parser`（仅 dev）扫描代码提取 key，CI 中检查 `en/` 是否覆盖全部 key（其他语言的缺失允许）

| 风险 | 影响 | 缓解 |

## 11. 关键决策记录（ADR-style）

- **D1**：翻译 JSON 放 `shared/` 而非 `core/` 或 `main/` — 让两个进程都能直接 import，且 `notificationCatalog.ts` 已为此设立先例
- **D2**：i18next 工厂放 `core/i18n/` 而非 `shared/` — 工厂含运行时初始化逻辑，`shared/` 严格应为数据/类型；`core/` 允许纯逻辑
- **D3**：不引入 `i18next-http-backend` — Electron asar 内 HTTP 加载需自定义协议；直接 import JSON 简单且支持 tree-shaking
- **D4**：不新增 IPC 通道 — 严格遵守 `project_memory.md` 的硬约束；语言通过 `SAVE_CONFIG` 流动，主进程在 `applyConfigPatch` 内响应
- **D5**：跨窗口即时同步非 MVP — 避免新增推送通道；下次重启或用户主动操作时同步可接受
- **D6**：`gamedata.json` 物品名翻译不在本设计内 — 需独立设计并行 catalog，避免本设计范围爆炸
