## 0. 原始需求复述（逐字）

1. 「不可用的提示，明显不应该提示了。」
2. 「祈愿也要统计是什么硬币祈愿的。」
3. 「祈愿结果也要匹配到日志中。」
4. 「祈愿次数，产出物品数和最近祈愿时间的展示。」
5. 「跟掉落页面布局一样，先显示背包硬币的种类和数量，然后旁边是最近祈愿结果，什么物品什么硬币和时间，下方是自动分类，将结果与硬币相对应。」

## 1. 产品目标与成功标准

**一句话目标**：把「只能看产出物品」的祈愿页，升级为「按**献祭硬币**归因 + 对齐掉落页布局」的祈愿分析页，并清掉冗余提示、修复祈愿行在记录页被误认为「通关」的老缺陷。

**成功标准（可验证）**：

| # | 成功标准 | 验证方式 |
|---|---|---|
| S1 | 祈愿页不再出现 `unavailable` 提示横幅；有数据即有内容展示 | 关闭 live reader 打开祈愿页（本地复现），无该横幅；i18n 4 语言中 `unavailable` 键被移除或不再被引用 |
| S2 | 每条可归因的祈愿结果能看到「是什么硬币祈愿的」；不可实证归因时能看到候选硬币集合 + 概率 | 使用 3444 条真实归档 + 2 条祈愿行样本回归；`coinAttribution` 字段非空或 `candidates` 非空 |
| S3 | 记录页中祈愿结果行**不再**被显示为金色「通关」徽章 | 记录页搜索祈愿行，`sourceFit` 不为 `clear`，徽章归属为祈愿类 |
| S4 | 祈愿页顶部同时展示「祈愿次数 / 产出物品数 / 最近祈愿时间」三项 | UI 目视 + 快照测试 |
| S5 | 祈愿页布局与掉落页同构：上（左：背包硬币种类+数量，右：最近祈愿结果）→ 下（按硬币分组的自动分类） | UI 目视对比 `Loot.tsx` |
| S6 | 品质分布从 8 桶扩展到 11 桶（新增 `BEYOND / DIVINE / COSMIC`，保留 `UNKNOWN`），4 语言文案齐全 | 单测覆盖 11 桶顺序；i18n 键完整性检查 |

**非目标（本轮不做）**：不改动存档（只读约束不变）；不新增 IPC 通道；不接入游戏侧 `Satistics_TotalOfferingCount`（沿用 `gameOfferingItemCount: null`）。

## 4. 数据模型草案（产品视角，最终接口由架构师定稿）

> 仅给**字段需求 + 口径定义**，不给实现。

### 4.1 硬币归因条目（最近结果 / 历史）

```ts
/** 硬币归因置信度。 */
type CoinAttributionConfidence =
  | "observed"   // 差分优先：从 materialStacks 数量差分标定出唯一硬币（实证）
  | "inferred"   // 候选兜底：由 offerings.json loot 表反查得到候选集合（推断）
  | "unknown";   // 两者皆不可用（如 lookup 缺失且差分不可靠）

/** 一枚候选硬币。 */
interface WishCoinCandidate {
  coinKey: number;    // 160001–160010
  poolPct: number;    // 该硬币掉落表内此物品的池概率（来自 offerings.json）
}

/** 一条祈愿结果的硬币归因。 */
interface WishCoinAttribution {
  confidence: CoinAttributionConfidence;
  /** confidence === "observed" 时为唯一硬币；否则 null。 */
  coinKey: number | null;
  /** confidence === "inferred" 时的候选集合，按 poolPct 降序；observed/unknown 时为空数组。 */
  candidates: WishCoinCandidate[];
  /** 归因依据（诊断用，可选）：观察到的数量差分 / 候选来源。 */
  basis?: string;
}
```

### 4.2 「最近祈愿结果」条目字段

```ts
interface WishRecentResult {
  wallTime: number;              // 时间（epoch 秒）
  gameTime?: string;             // 游戏内时间串（参考）
  name: string;                  // 物品名
  grade: WishGrade;              // 品质（11 桶）
  count: number;                 // 件数（>=1）
  coin: WishCoinAttribution;     // 硬币归因（物品 / 硬币 / 时间 三要素之「硬币」）
}
```

### 4.3 硬币维度聚合（按 coinKey 分组）

```ts
/** 单个硬币分区的产出物品条目。 */
interface WishCoinGroupItem {
  name: string;
  count: number;                 // 该物品被此硬币产出的件数
  grade: WishGrade;
}

/** 一个硬币分区（对标 LootBoxSection 的 per-box 分区）。 */
interface WishCoinGroup {
  coinKey: number;               // 分区键
  coinName: string;              // 硬币显示名（来自 lookup）
  grade: WishGrade;              // 硬币自身品质
  offeringCount: number;         // 该硬币发起的祈愿次数
  itemCount: number;             // 该硬币产出的物品总件数
  items: WishCoinGroupItem[];    // 区內物品排行（次数降序）
}

/** 未能归因到具体硬币的分区（候选/未知），独立成组。 */
interface WishUnattributedGroup {
  items: WishCoinGroupItem[];    // 每个条目可带 candidates
}
```

### 4.4 背包硬币面板字段

```ts
interface WishHeldCoin {
  coinKey: number;               // 160001–160010
  name: string;                  // 名称（lookup）
  grade: WishGrade;              // 品质
  quantity: number;              // 背包/仓库槽位 Quantity 求和（materialStacks[coinKey]）
  iconPath: string;              // item-<id>
}
```

### 4.5 祈愿页顶层聚合输出（建议挂在既有 `Stats.wish` 下）

```ts
interface WishStats {                         // 既有结构，新增字段（增量）
  // ...既有字段保持不变（见 §6 口径不变量）...
  heldCoins: WishHeldCoin[];                  // 背包硬币种类+数量
  recentResults: WishRecentResult[];          // 最近祈愿结果（倒序）
  coinGroups: WishCoinGroup[];                // 按硬币分组的分区
  unattributed: WishUnattributedGroup;       // 未归因条目
}
```

**口径定义**：
- `quantity` 口径 = **背包 + 仓库槽位 Quantity 求和**（复用既有 `materialStacks` 管道，无新数据源）。
- 硬币判别键 = `lookup_items.json` 中 `materialType === "OFFERING"`（可靠判据），或 `itemKey ∈ [160001,160010]`。
- `observed` 归因口径：祈愿事件前后两帧 `materialStacks` 差分 **仅一枚** coinKey 减少 > 0 → 该硬币；否则不产 `observed`。
- `inferred` 归因口径：`offeringSourcesForItem(model, itemKey)` 反查，命中即候选集（**多对多关系，不猜测唯一**）。
- 归因**绝不猜测**：无法确定唯一硬币时一律走 `inferred`/`unknown`，不虚构 `coinKey`（与既有 `grade` 的「无法映射一律 UNKNOWN」一致）。

## 6. 口径与不变量（不得擅改）

| # | 既有不变量 | 本次是否触碰 | 说明 |
|---|---|---|---|
| I1 | **双计数口径**：`offeringCount`（按结果行计）+ `itemCount`（行内数量，缺省 1） | **不触碰** | 新增硬币维度是**追加**聚合，不改既有两计数语义 |
| I2 | **会话重置语义**：`reset()` = `*Session` 归零、累计不变、`sessionWishStart` 重置为现在 | **不触碰** | 硬币分组沿用同一累计/会话口径，重置行为不变 |
| I3 | **归档不随会话重置清空**：`wish_record.json` 长期归档不因会话重置而清 | **不触碰** | P1-5 只**追加**硬币字段，不改生命周期 |
| I4 | **bulk 护栏**：`initial=true` 回灌行标 `bulk`，计入累计/会话/历史，**不进滚动速率窗** | **不触碰** | 归因模块对 bulk 行同样不得伪造差分（bulk 行 wallTime ≠ 事件时刻） |
| I5 | **零新增 IPC**：祈愿数据只走既有 `IPC.STATS`（广播）+ `IPC.RESET`（重置） | **不触碰** | 新增字段随既有 `Stats.wish` 下发；背包硬币复用既有 inventory 管道；**不新增通道** |
| I6 | **只读存档**：从不修改游戏存档 | **不触碰** | 差分只**读取**两帧 `materialStacks` 对比，绝不写回 |
| I7 | **品质绝不猜测**：无法映射一律 `UNKNOWN` | **延续** | 硬币归因同原则：无法唯一确定 → `inferred`/`unknown`，不虚构 coinKey |
